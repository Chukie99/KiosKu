# KiosKu – Blueprint Lengkap

## 1. Ringkasan & Tujuan

**Masalah:**
Warung/toko kelontong butuh transaksi kasir yang cepat layaknya minimarket modern (misal Alfamart), tapi mayoritas software kasir yang ada mahal, butuh hardware scanner khusus, atau mengharuskan semua barang punya barcode tercetak. Kenyataannya banyak barang kelontong (beras, cabai, gula curah, dll) tidak punya barcode dari pabrik, sehingga proses input manual jadi lambat dan rawan salah hitung.

**Solusi:**
KiosKu adalah aplikasi kasir Android yang memanfaatkan kamera HP sebagai barcode scanner (tanpa perlu beli alat scanner terpisah), dan menyediakan cara cepat memilih barang tanpa barcode lewat daftar produk, kategori, pencarian, dan tombol favorit. Data produk, stok, dan transaksi tersimpan terpusat di PC/laptop toko yang bertindak sebagai server lokal, diakses oleh HP Android kasir melalui jaringan WiFi lokal (tanpa perlu internet/cloud).

**Nilai Utama:**
- Transaksi cepat tanpa perlu beli hardware barcode scanner mahal
- Barang tanpa barcode tetap bisa dijual cepat lewat menu pilih/favorit
- Stok otomatis berkurang & ada alert kalau mau habis
- Laporan penjualan real-time (harian/bulanan, barang terlaris)
- Data 100% milik toko sendiri, tersimpan lokal di PC, tidak bergantung cloud pihak ketiga
- Gratis dari biaya payment gateway karena QRIS/e-wallet dikonfirmasi manual dulu

## 2. Persona Pengguna

| Persona | Kebutuhan Utama |
|---|---|
| **Pemilik Toko** | Melihat laporan omzet & barang laris, mengelola daftar produk & harga, memantau stok, melihat daftar utang pelanggan, memastikan data aman (backup) |
| **Kasir** | Transaksi secepat mungkin, scan barcode atau pilih produk dengan mudah, hitung kembalian otomatis, cetak struk, catat utang pelanggan jika diminta |

*(Catatan: pada versi ini, pemilik & kasir menggunakan akses yang sama tanpa pembeda role/login terpisah. Role-based access akan ditambahkan di fase berikutnya.)*

## 6. Arsitektur Sistem

- **Frontend Android:** Flutter 3.x (Dart), Riverpod untuk state management, berjalan sebagai client yang terhubung ke backend via REST API di jaringan lokal (LAN)
- **Frontend PC (Dashboard Web):** React 18 + TypeScript + Vite, Tailwind CSS + shadcn/ui, disajikan langsung oleh backend FastAPI sebagai static file, diakses via browser (`http://localhost:8000` atau IP LAN PC)
- **Backend:** Python FastAPI + Uvicorn, berjalan sebagai server lokal di PC/laptop toko (bukan cloud), menangani seluruh logika bisnis (transaksi, stok, laporan, utang)
- **Database:** SQLite (file `kiosku.db` tersimpan di PC), dipilih karena ringan, embedded, dan mudah untuk proses backup (cukup salin file)
- **Autentikasi:** PIN lokal (disimpan hashed dengan bcrypt di tabel `app_settings`), tanpa layanan autentikasi eksternal karena skala 1 toko tanpa role terpisah
- **Printer Thermal:** Terhubung langsung ke HP Android kasir via USB-OTG atau Bluetooth (ESC/POS command), bukan lewat PC
- **Hosting:** Sepenuhnya lokal (on-premise) — backend berjalan di PC toko, Android terhubung via WiFi router lokal, tidak membutuhkan koneksi internet untuk operasional kasir sehari-hari
- **Sinkronisasi Offline:** Android menyimpan transaksi sementara di SQLite lokal (`sqflite`) dengan flag `synced=false` saat koneksi ke PC putus, lalu otomatis push ke server saat koneksi kembali

## 7. Skema Database (SQL)

> Catatan: menggunakan SQL DDL langsung (bukan Prisma) karena backend menggunakan Python FastAPI + SQLAlchemy + SQLite.

```sql
CREATE TABLE categories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE products (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    sku TEXT UNIQUE,                    -- kode barang, auto-generate jika tidak ada barcode
    barcode TEXT UNIQUE,                -- NULL jika produk tidak punya barcode pabrik
    name TEXT NOT NULL,
    category_id INTEGER REFERENCES categories(id),
    photo_path TEXT,                    -- path lokal foto produk
    unit_base TEXT NOT NULL DEFAULT 'pcs',
    price_buy REAL DEFAULT 0,           -- harga modal
    price_sell REAL NOT NULL,           -- harga jual satuan dasar
    stock REAL NOT NULL DEFAULT 0,
    stock_alert_threshold REAL DEFAULT 5,
    is_favorite BOOLEAN DEFAULT 0,
    is_active BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE product_units (            -- multi-satuan (mis. rokok: batang & bungkus)
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id INTEGER NOT NULL REFERENCES products(id),
    unit_name TEXT NOT NULL,
    conversion_qty REAL NOT NULL,       -- jumlah unit_base per unit ini
    price_sell REAL NOT NULL
);

CREATE TABLE customers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    phone TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE transactions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    invoice_no TEXT UNIQUE NOT NULL,
    customer_id INTEGER REFERENCES customers(id),   -- NULL jika bukan transaksi utang
    total_amount REAL NOT NULL,
    discount_amount REAL DEFAULT 0,
    payment_method TEXT NOT NULL,       -- 'tunai','qris','ewallet','split','utang'
    cash_received REAL,
    change_amount REAL,
    payment_split_json TEXT,            -- detail rincian jika split payment
    status TEXT NOT NULL DEFAULT 'selesai',  -- 'selesai','void','retur'
    device_id TEXT,
    synced BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE transaction_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    transaction_id INTEGER NOT NULL REFERENCES transactions(id),
    product_id INTEGER NOT NULL REFERENCES products(id),
    product_name_snapshot TEXT NOT NULL,
    unit_name TEXT NOT NULL,
    qty REAL NOT NULL,
    price_per_unit REAL NOT NULL,
    subtotal REAL NOT NULL
);

CREATE TABLE debts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    customer_id INTEGER NOT NULL REFERENCES customers(id),
    transaction_id INTEGER REFERENCES transactions(id),
    amount REAL NOT NULL,
    amount_paid REAL DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'belum_lunas',  -- 'belum_lunas','sebagian','lunas'
    due_date DATE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE stock_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    product_id INTEGER NOT NULL REFERENCES products(id),
    change_qty REAL NOT NULL,           -- negatif = keluar, positif = masuk
    reason TEXT NOT NULL,               -- 'transaksi','restock','retur','koreksi'
    reference_id INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE app_settings (
    key TEXT PRIMARY KEY,
    value TEXT
);
```

## 9. Non-Functional Requirements

- **Performa:** Respon API di jaringan lokal < 300ms; pencarian produk di antara ribuan item menggunakan index database (`sku`, `barcode`, `name`) agar tetap instan
- **Keamanan:** PIN disimpan dalam bentuk hash (bcrypt), tidak ada data yang dikirim ke server pihak ketiga/cloud manapun — semua data tetap di jaringan lokal toko
- **Reliabilitas:** Backup otomatis harian (copy file `kiosku.db` ke folder terpisah dengan timestamp), mode offline dengan antrian sinkronisasi otomatis retry
- **Skalabilitas Data:** Database didesain menangani ribuan produk dan ribuan transaksi tanpa penurunan performa signifikan pada skala 1 toko
- **Usability:** Elemen UI kasir berukuran besar dan kontras tinggi agar cepat dioperasikan; konfirmasi wajib sebelum aksi destruktif (void, hapus produk)
- **Kompatibilitas:** Android 8.0 (API 26) ke atas; Windows 10/11 untuk server backend & dashboard
- **Ketersediaan Offline:** Aplikasi kasir Android tetap berfungsi penuh tanpa internet, hanya membutuhkan jaringan WiFi lokal ke PC (mode offline sementara jika WiFi putus)
- **Aksesibilitas:** Kontras warna teks-background memenuhi standar WCAG AA minimal, ukuran font dasar tidak lebih kecil dari 14px

## 10. Instruksi untuk AI Developer (OpenCode CLI)

Baca seluruh blueprint ini secara menyeluruh sebelum mulai coding. Bangun aplikasi **KiosKu** lengkap sesuai spesifikasi di atas, terdiri dari tiga bagian:

1. **Backend** (Python FastAPI + SQLite) — implementasikan seluruh endpoint di Section 8, skema database di Section 7, termasuk logika bisnis: pengurangan stok otomatis saat transaksi, perhitungan kembalian, validasi void/retur, kalkulasi laporan, dan proses backup otomatis.
2. **Aplikasi Android** (Flutter) — implementasikan seluruh halaman di Section 3.4, termasuk scan barcode kamera, mode offline dengan sinkronisasi otomatis, dan integrasi printer thermal USB/Bluetooth.
3. **Dashboard Web PC** (React + shadcn/ui, disajikan oleh backend) — implementasikan halaman laporan dan kelola produk untuk diakses dari browser PC.
